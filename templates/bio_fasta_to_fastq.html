What this FASTA to FASTQ converter does

FASTA stores a header and a sequence. FASTQ stores the same information plus a per-base quality score, in four lines per record: @header, sequence, +, and a quality string of the same length as the sequence. Some pipelines and tools insist on FASTQ input even when quality data is irrelevant — for example when testing a pipeline before real data is available, or when a wrapper checks the file extension.

This converter adds a uniform quality score to every base so the output is valid FASTQ. The sequence letters are not changed.

What quality score is used?

By default every base gets I, which is Phred score 40 in the standard Sanger encoding — the highest quality a typical sequencer reports. Treat these as placeholder values, not real measurements. If a downstream step uses quality scores for trimming or variant calling, the placeholder will distort the result.

FASTQ quality is encoded as ASCII: Phred 40 is the character I in the Sanger scale (ASCII 73). Older Illumina encodings used different offsets; this tool writes the modern Sanger/Illumina 1.8+ scale.

When to use it

  • A pipeline requires FASTQ input but the quality data is irrelevant.
  • You are preparing a test file for a workflow that expects FASTQ.
  • You need a valid four-line FASTQ record from a reference sequence.
  • You are converting a small FASTA file for a tool that checks the format.

Do not use placeholder qualities for variant calling, trimming, adapter detection or any analysis that depends on per-base confidence. For real FASTQ data, start from the sequencer output.

Frequently asked questions

Are my sequences modified?

No. Sequence letters are kept exactly as they appear; line wrapping is normalised and quality strings are generated to match each sequence length.

Can I convert many records at once?

Yes — paste a multi-record FASTA file and every record is converted, in order. Each record gets its own four-line FASTQ block.

Are the placeholder quality scores real?

No. They are a uniform Phred 40 value. They make the file valid FASTQ but carry no information about the actual base quality.

Does it handle RNA sequences?

Yes, the sequence letters are preserved. The quality string is generated by length, so U and other IUPAC letters are handled the same way as A/C/G/T.

Can I choose a different quality character?

The web tool uses I. For a different placeholder, use the API or a script with a FASTQ writer.

Why does the output have one line per sequence?

The converter normalises line wrapping to the standard four-line FASTQ layout. The sequence itself is unchanged.
