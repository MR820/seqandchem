What this SDF to SMILES converter does

SDF (Structure-Data File, also called SD file) is the most common format for compound libraries. Each record stores one molecule with its 2D or 3D coordinates plus attached properties. Converting to SMILES gives you a compact, one-line representation for each molecule that is easy to store in a CSV, load into a database or pass to another tool.

Paste a whole SDF with many records (separated by $$$$) and you get one SMILES per line, in the same order. This is the usual way to flatten a screening library. The reverse direction is available in SMILES to SDF.

Why convert SDF to SMILES?

  • Smaller files — SMILES is a one-line string; an SDF record carries a full atom table, bond table and property block.
  • CSV and spreadsheet friendly — one SMILES per row is easy to join with assay data or compound IDs.
  • Database search — most chemistry databases accept SMILES as a query or storage format.
  • Similarity and substructure tools — SMILES is the input for Tanimoto similarity and substructure search.
  • Scripts and models — SMILES is the standard text representation in cheminformatics code.

Multi-record files are supported

An SDF file can contain thousands of records. The converter reads each record up to the $$$$ separator and writes one SMILES per line. The output order matches the input order, so you can join the result back to a source table by row number. If a record cannot be parsed, check that it has a valid V2000/V3000 header and a complete atom block.

For very large libraries, use the batch converter or the API; the web textarea is intended for interactive use.

What is preserved and what is lost

InformationIn SMILES output?
Connectivity and bond ordersYes
Formal chargesYes
Defined stereochemistryYes, when the SDF has wedge/hash bonds or stereo flags
2D/3D coordinatesNo — SMILES does not store coordinates
Data fields (name, assay values, IDs)No — properties are dropped
Record orderYes — one line per record, same order

Because properties are lost, keep the source SDF or a separate property table if you need the annotations. Joining by record order is the simplest workflow.

SDF vs MOL

A MOL file holds exactly one molecule. An SDF file is essentially a MOL record followed by data fields and a $$$$ separator, repeated for as many molecules as needed. If your file contains a single MOL record, use MOL to SMILES; for a library, this page is the right tool.

Worked example

An SDF with two records — aspirin followed by caffeine — produces two lines: the aspirin SMILES on line 1 and the caffeine SMILES on line 2. The property fields attached to each record are not included. If you enable “Canonicalize”, the output uses a canonical SMILES form, which is useful for deduplication but may differ from the SMILES you started with.

Common uses

  • Flattening a vendor or screening library into a CSV column.
  • Preparing structures for a similarity search or clustering run.
  • Importing a compound collection into a database that stores SMILES.
  • Deduplicating records by canonical SMILES or InChIKey (SMILES to InChI).
  • Feeding a machine-learning pipeline that expects SMILES strings.

Frequently asked questions

Are SDF properties lost?

Yes — SMILES only stores the structure. Any SDF data fields are dropped. If you need to keep them, convert to a format that preserves annotations, or join the SMILES back to your source table by record order.

Which SMILES flavour is produced?

A standard OpenBabel SMILES. Enable “Canonicalize” if you need the canonical form for deduplication. Canonical SMILES is toolkit-specific, so do not compare strings produced by different toolkits.

Does it preserve stereochemistry?

Yes, when the SDF record defines it through wedge/hash bonds or atom stereo flags. A flat 2D record without stereo information cannot produce a stereo-defined SMILES.

Can I convert a large SDF file?

The web page is intended for interactive files. For a large library, use the batch converter or call the API with the SDF as the input and SMILES as the output.

Why do I get fewer lines than records?

Some records may be empty, malformed or contain only properties without a structure. Check the input around the missing record; the converter skips records it cannot parse. A valid SDF record must have an atom block and a bond block.

Does it handle V3000 SDF files?

OpenBabel reads V2000 and V3000 records. If a V3000 record uses a feature that the converter does not support, that record may fail or lose the feature; check the output and the record count.
