What this chemical format converter does

  
Any format OpenBabel can read can be converted to any format it can write. That covers more
     than 190 formats, including SMILES, InChI, InChIKey, MOL, SDF, MOL2, PDB, XYZ, CML, PNG and
     SVG. Paste the structure, choose an input and output format, and convert. For a single-purpose
     page with a focused explanation, use one of the one-click converters listed above.

How to choose the right format

  
    
    
  • For a database or a script — SMILES or InChI. InChI is canonical by
        standard; SMILES is compact and widely accepted.
    • 
    
  • For a structure editor — MOL or SDF with 2D coordinates.
    • 
    
  • For docking — SDF or PDBQT, depending on the docking program.
    • 
    
  • For a viewer — PDB, SDF or MOL2 with 3D coordinates.
    • 
    
  • For a paper or slide — SVG (scalable) or PNG (raster).
    • 
  


  
Options explained

  
    
    
  • 3D coordinates — runs a force-field conformer search instead of a flat 2D
        layout. It can take a few seconds for a flexible molecule.
    • 
    
  • Canonicalize — outputs the canonical SMILES form, useful for
        deduplication. Canonical SMILES is toolkit-specific; do not compare strings from
        different toolkits.
    • 
    
  • Add / remove hydrogens — controls explicit hydrogen atoms in the output.
    • 
    
  • Deduplicate — removes duplicate structures when converting a list.
    • 
  


  
Worked example

  
Take aspirin, CC(=O)Oc1ccccc1C(=O)O. Converting to MOL gives a V2000 block you
     can open in ChemDraw; converting to InChI gives
     InChI=1S/C9H8O4/c1-6(10)13-8-5-3-2-4-7(8)9(11)12/h2-5H,1H3,(H,11,12); converting
     to SDF with 3D coordinates gives a multi-purpose structure file for a viewer or a modelling
     pipeline. The connectivity is the same in all three; what changes is the representation and
     the amount of metadata.


  
Limitations

  
    
    
  • One molecule vs a library — this page converts the pasted records; for a
        large library, use the batch converter.
    • 
    
  • Properties are not preserved — SDF data fields, PDB headers and CML
        annotations do not survive a conversion to a format that has no place for them.
    • 
    
  • Coordinates are not always preserved — SMILES and InChI do not store
        coordinates; a 2D layout or a 3D conformer must be generated.
    • 
    
  • Not every pair is meaningful — converting a protein PDB to a small-molecule
        line notation can produce a disconnected string. Convert the ligand fragment instead.
    • 
  


  
Frequently asked questions

  
How many formats are supported?

  
More than 190, limited by the OpenBabel build on the server. The dropdown lists the formats
     that can be read or written.

  
Does conversion preserve stereochemistry?

  
Yes, when the source format and the target format both represent it. A source without stereo
     information cannot produce a stereo-defined output.

  
Why is my SDF larger than my SMILES?

  
SDF stores an explicit atom table, bond table and coordinates; SMILES is a compact graph
     notation. The extra bytes are the structure data and metadata.

  
Can I convert a whole library?

  
Use the batch converter for up to 5,000 records, or the
     API for programmatic access.

  
Can I convert to an image?

  
Yes — choose PNG or SVG. For a larger raster or a different layout, use the
     PNG or SVG tool.

  
Why does the conversion fail for some inputs?

  
The input may be malformed, unsupported or missing a required block (for example, a MOL file
     without an atom table). Check the error message and the source file.
