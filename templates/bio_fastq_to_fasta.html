What this FASTQ to FASTA converter does

FASTQ stores a header, a sequence and a per-base quality string. FASTA stores only the header and the sequence. This converter drops the quality string and writes a standard FASTA record for each read, preserving the identifier and the sequence.

It is useful when you no longer need per-base confidence: after trimming and filtering, most aligners, assemblers, BLAST searches and sequence databases only require the sequence itself.

Why drop quality scores?

Quality strings often double the size of a sequencing file. Once you have trimmed and filtered your reads, the quality data is usually not needed downstream. Converting to FASTA makes files smaller and compatible with tools that do not read FASTQ.

Quality data is discarded permanently. If you may need to re-run trimming, variant calling or quality-based filtering, keep the original FASTQ file — the conversion is one-way.

Supported FASTQ variants

The converter reads standard four-line FASTQ: header, sequence, a line starting with +, and the quality string. It supports Sanger and Illumina 1.8+ encoding because it does not interpret the quality characters — it simply removes them. Multi-line sequence records, used by a few older tools, are not supported.

When to use it

  • After trimming and filtering, when only the sequence is needed.
  • Preparing reads for an aligner, assembler or BLAST that expects FASTA.
  • Reducing file size for storage or transfer.
  • Submitting sequences to a database that does not accept FASTQ.

For the reverse direction, use FASTA to FASTQ. For a full explanation of the formats, see the FASTA vs FASTQ guide.

Frequently asked questions

Which FASTQ variants are supported?

Standard four-line FASTQ (Sanger, Illumina 1.8+) is supported. Multi-line sequence records, used by a few older tools, are not. A record whose quality string is not the same length as the sequence, whose quality characters fall outside ASCII 33-126, or that is missing a line is rejected. Blank lines are allowed only between records.

Are the identifiers preserved?

Yes. The @ header becomes a > header with the same content, including any description after the identifier.

Can I recover the quality scores after conversion?

No. The conversion is one-way; the quality data is removed. Keep the original FASTQ file if you may need it.

Does it trim or filter reads?

No. It only changes the format. Trimming, adapter removal and quality filtering should be done before conversion with a dedicated tool.

How many records can I convert?

The web textarea is intended for interactive files. For a large FASTQ file, use the API or a command-line tool such as seqtk.

What happens to the + line?

It is discarded along with the quality string. FASTA has no equivalent line.
