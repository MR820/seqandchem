What this MOL to SMILES converter does

A MOL file is a single-molecule structure file in the MDL format — the same record format used inside SDF files, just without the property block and without the record separator. This converter turns one MOL file into a SMILES string that you can paste into a database, a script or another chemistry tool.

The converter reads the atom and bond tables, perceives aromaticity where possible and writes a SMILES string. If the MOL file has 2D or 3D coordinates, they are used to understand the structure but are not part of the SMILES output; SMILES carries connectivity and bond orders, not coordinates.

Common use cases

  • You drew a structure in ChemDraw, Marvin or Avogadro and need the SMILES.
  • You have a MOL file from a vendor catalogue and want to search it in a database.
  • You are building a dataset and need a uniform text representation.
  • You want to compare a structure with a SMILES-based similarity or substructure tool (Tanimoto similarity, substructure search).

What is preserved

  • Connectivity — atoms and bonds from the MOL bond block.
  • Bond orders — single, double and triple bonds; aromatic rings are written in Kekulé form or as aromatic atoms where the toolkit can perceive them.
  • Formal charges — charge fields in the atom block become charged atoms in the SMILES.
  • Stereochemistry — wedge/hash bonds and atom stereo flags are converted to @ or @@ when the MOL file defines them.
  • Isotopes — isotope labels, when present, are written into the SMILES.

What can go wrong

  • Missing bond orders — a MOL file without bond orders (for example, a file built only from coordinates) can produce a SMILES with the wrong bond orders. Check the structure before using it for registration.
  • Hydrogens — explicit hydrogens in the MOL file become explicit atoms in the SMILES unless the converter removes them. Use the “Remove hydrogens” option for a compact string.
  • Salts and mixtures — a MOL file with disconnected components produces a SMILES with multiple components separated by dots. Split the file if you need one molecule.
  • Aromaticity — different toolkits perceive aromaticity differently, so the same MOL file can produce a Kekulé or an aromatic SMILES depending on the converter.
  • Large or malformed files — a truncated MOL file or a V3000 file with unsupported features may fail; check the error message and the atom count line.

Worked example

Aspirin drawn in ChemDraw or downloaded as a MOL file has the connectivity of CC(=O)Oc1ccccc1C(=O)O. Paste the MOL file into the converter and you get a SMILES with the same acetyl, aromatic ring and carboxylic acid groups. The exact string may differ from the one in a database because SMILES is not unique; the molecule is the same. To go back the other way, use SMILES to MOL.

MOL, SDF and other formats

SDF is essentially a MOL file followed by data fields and a $$$$ separator, so one SDF file can hold many molecules while a MOL file holds exactly one. If your file has multiple records, use SDF to SMILES instead. For a different output format, the format converter accepts MOL, SDF, PDB, XYZ, MOL2 and more.

Frequently asked questions

MOL vs SDF — what is the difference?

SDF is essentially a MOL file followed by data fields and a $$$$ separator, so one SDF file can hold many molecules while a MOL file holds exactly one. If your file has multiple records, use SDF to SMILES instead.

Why is my SMILES different from the original?

SMILES is not a unique string: the same molecule can be written in many valid ways. The converter may produce a different valid SMILES from the one you started with. Compare connectivity and stereochemistry, not string equality.

Does it preserve stereochemistry?

Yes, when the MOL file has wedge/hash bonds or atom stereo flags. A flat 2D MOL file without stereo information cannot define stereochemistry, so the output will be unspecified.

Can I convert multiple MOL files at once?

This page converts one MOL record. For a multi-record SDF file, use SDF to SMILES; for a library, use the batch converter or the API.

Does it handle V3000 MOL files?

OpenBabel reads V2000 and V3000 MOL files. If a V3000 file uses a feature that the converter does not support, the conversion may fail or lose that feature; check the result.

What about charges and salts?

Formal charges are preserved. Salts and counter-ions appear as separate dot-separated components in the SMILES. If you want the parent compound only, remove the counter-ion before converting.
